# QQ/微信做不到的校园专属层 — 产品策略白皮书

> CampusLink 不需要替代 QQ/微信，而是构建一个**校园专属层**，让学生的校园生活在 QQ/微信之上多一个有价值的维度。

---

## 一、核心洞察：QQ/微信的先天缺陷

QQ 和微信是**通用社交工具**，它们的底层逻辑是**聊天**，所有功能围绕聊天展开。这导致三个不可调和的结构性问题：

### 1. 信息结构扁平化 — "刷过去就没了"

QQ/微信里所有信息都挤在**聊天列表**里：通知、闲聊、表情包、文件、二手信息……全部混在一起。结果是：
- 一条二手书出售帖发到年级群 → **30 秒后被拼多多砍价链接刷走**
- 学委发的重要考试通知 → **被 "收到" 接龙淹没**
- 你想找上周发布的校园活动链接 → **翻 500 条消息也找不到**

**CampusLink 能做而 QQ/微信做不到的**：结构化信息。帖子有分类、有标签、有搜索、有存档，信息不会随着时间线消失。

### 2. 社交关系泛化 — "太杂了"

微信群/QQ群承载了太多角色：家人、朋友、同学、老师、微商、快递……每一个消息通知都在**争夺同一个注意力池**。结果是：
- 不想让同学看到自己的朋友圈
- 不想在班级群里闲聊打扰别人
- 想匿名说点心里话 → 做不到，因为群里全是实名

**CampusLink 能做而 QQ/微信做不到的**：角色隔离。在 CampusLink 里我就是 **"本校学生"** ，不是"XXX 班的小张"——可以实名交易、匿名吐槽、兴趣交友，不会混入私人社交圈。

### 3. 校园场景缺失 — "没有原生适配"

微信做了微信支付、小程序、视频号，但**没有任何一个团队专门为校园场景设计功能**。结果是：
- 课表？→ 要去超级课程表
- 成绩？→ 要去教务系统（还得用电脑）
- 二手交易？→ 闲鱼
- 失物招领？→ 群发消息碰运气
- 活动通知？→ 等学委转发

**CampusLink 能做而 QQ/微信做不到的**：场景原生。所有功能从第一天起就是为校园场景设计的，不是在聊天上面拼凑。

## 二、校园专属层的五层架构

```
┌─────────────────────────────────────────┐
│         第五层：身份与信任层              │
│    （实名认证 + 学籍背书 + 信誉分）       │
├─────────────────────────────────────────┤
│         第四层：交易与服务层              │
│    （二手交易 + 担保支付 + 跑腿互助）     │
├─────────────────────────────────────────┤
│         第三层：社交与社区层              │
│    （校园圈 + 匿名 + 兴趣圈子 + 话题）    │
├─────────────────────────────────────────┤
│         第二层：信息与内容层              │
│    （帖子分类 + 搜索 + 通知聚合 + OCR）   │
├─────────────────────────────────────────┤
│         第一层：校园基础设施层            │
│    （课表 + 成绩 + 考试 + 教室 + 教务）   │
└─────────────────────────────────────────┘
                ▲
                │ 依赖关系（下层支撑上层）
                │
        底层价值最硬、不可替代性最强
```

### 第一层：校园基础设施层 — 每天打开的理由

这一层是 CampusLink 的 **"锚"** 。QQ/微信永远不可能做这些，因为：
- 需要对接学校教务系统（数据壁垒）
- 需要学校官方合作（关系壁垒）
- 需要深度理解中国高职院校的排课逻辑（认知壁垒）

**核心功能**：

| 功能 | 学生价值 | 竞争壁垒 |
|------|---------|---------|
| 课表管理（教务同步） | 每天看 3-5 次，紫星 自动同步 | 需教务接口 |
| 成绩/绩点查询 + 推送 | 出分焦虑终结者 | 需教务接口 |
| 考试安排自动同步 | 不再漏考、记错时间 | 需教务接口 |
| 教室空闲查询 | 找自习室不求人 | 需教务数据 |
| 调课/停课通知推送 | 不再走错教室 | 需教务接口 + Push |

**成功指标**：学生每天主动打开 CampusLink ≥ 2 次，其中 1 次一定是因为课表。

### 第二层：信息与内容层 — 比 QQ 群好用 10 倍的信息管理

这一层解决的是 **"QQ 群消息刷屏 → 信息丢失"** 的痛点。

**核心差异**：

| 维度 | QQ/微信群 | CampusLink |
|------|----------|-----------|
| 信息结构 | 时间线扁平，混在一起 | 分类+标签+置顶+精华 |
| 可检索性 | 没有搜索或搜索极差 | 全文搜索+分类筛选 |
| 信息持久性 | 30 分钟后被刷走 | 永久保存，可归档 |
| 通知方式 | 全量推送，骚扰 | 按关注领域精准推送 |
| 信息可信度 | 无法验证 | 实名认证+校内身份背书 |

**关键功能**：
- **帖子分类体系**：二手 / 失物 / 拼车 / 兼职 / 活动 / 学习 / 生活
- **全文搜索**：搜帖子、搜评论、搜用户
- **通知聚合中心**：课表变动、交易进展、活动提醒、失物匹配——**只推送有用的，不推送废话**
- **OCR 能力**：课表拍照导入、名片/单据识别

### 第三层：社交与社区层 — 比校园墙更好的社交体验

QQ/微信是**熟人社交**，校园墙/贴吧是**匿名广场**。CampusLink 的校园圈要做的是**中间地带**——基于**同学身份**而非熟人关系的社交。

**QQ/微信做不到的校园社交**：
- **匿名+实名一键切换**：同一个帖子可以实名发，也可以匿名发，不需要换小号
- **兴趣圈子**：我关注"摄影圈"而不是关注某个人的朋友圈
- **话题聚合**：所有关于"食堂"的帖子自动归入同一个话题页
- **跨院系连接**：让我认识会计学院以外的同学，而不是永远只有自己班的人
- **内容质量筛选**：点赞/收藏/评论排序，而不是时间线刷屏

**三类关系对比**：

| | QQ/微信（熟人） | 校园墙/贴吧（陌生人） | CampusLink（同学） |
|--|---------------|-------------------|-----------------|
| 关系基础 | 现实熟人 | 完全匿名 | 本校学生身份 |
| 信任度 | 高 | 低 | 中高 |
| 信息质量 | 杂 | 低 | 中高（实名背书） |
| 场景覆盖 | 聊天 | 吐槽/爆料 | 交易+学习+生活+娱乐 |

### 第四层：交易与服务层 — 闲鱼做不到的校内交易

闲鱼的问题是**非校内人员混杂**，二手群的问题是**没有保障**。CampusLink 可以做到：

**校内交易专属能力**：

1. **校内信誉分系统**
   - 实名认证基底 + 交易记录累积
   - 成功交易 + 分，放鸽子/纠纷 − 分
   - 信誉分低的用户交易限制（比如只能先款后货）
   - **QQ/微信做不到**：它们没有信任体系

2. **面交码闭环**
   - 买家拍下 → 生成面交码 → 见面扫码确认 → 平台放款（如有担保）
   - 扫码确认后自动进入互评
   - **QQ/微信做不到**：没有交易状态机

3. **担保交易（可选进阶）**
   - 小额交易平台托管资金，确认收货后放款
   - 解决了"面交没保障"的问题
   - **闲鱼能做但不够好**：闲鱼不做校园场景适配

4. **失物智能匹配**
   - 捡到东西拍照上传 → 系统自动匹配失物帖子
   - 匹配成功 → 双方同时收到通知
   - **QQ/微信做不到**：没有结构化数据和匹配算法

### 第五层：身份与信任层 — 终极壁垒

这是最底层但也是最有价值的。CampusLink 积累的**校内身份和信任数据**，是 QQ/微信永远无法复制的。

**信任资产**：
- 学号实名认证 → 每个账号对应一个真实学生
- 院系/年级/班级信息 → 可验证的身份
- 交易记录 + 信誉分 → 历史行为追踪
- 管理员审核机制 → 内容质量把控

**为什么这是终极壁垒**：
- QQ/微信不可能要求学生实名学籍认证（隐私+合规问题）
- 闲鱼无法验证"本校学生"身份
- 学校官方系统有数据但无社交/交易产品能力

**CampusLink 可以做到的独特价值**：
- "本校学姐，信誉分 4.8，交易过 23 次" — 这句话在闲鱼上没法验证，在 CampusLink 里是事实
- 匿名吐槽帖，但发帖人是**真实学生**（尽管匿名显示）— 不会出现外校水军
- 活动报名不需要额外验证身份 — CampusLink 已经认证过了

## 三、专属层的防守逻辑：为什么别人抄不走

### 1. 网络效应 + 数据壁垒的叠加

| 层面 | 壁垒类型 | 追赶难度 |
|------|---------|:-------:|
| 课表/教务对接 | 关系+接口壁垒 | ⭐⭐⭐⭐⭐ |
| 实名学籍认证 | 信任+合规壁垒 | ⭐⭐⭐⭐ |
| 校内交易记录+信誉分 | 数据网络效应 | ⭐⭐⭐⭐ |
| 校园圈内容+圈子 | 网络效应 | ⭐⭐⭐ |
| 帖子分类+搜索 | 功能壁垒 | ⭐⭐ |

- QQ/微信如果要抄，需要先解决**接入教务系统**的问题（几乎不可能）
- 闲鱼如果要抄，需要先解决**实名学籍认证**的问题（成本极高）
- 一个新创业产品如果要抄，需要先解决**冷启动用户**的问题（CampusLink 已有先发优势）

### 2. 用户迁移成本的设计

每一层都设计了一个 **"迁移锚点"** ，让用户无法轻易离开：

| 层 | 迁移锚点 | 用户舍不得什么 |
|----|---------|-------------|
| 第一层（课表） | 课表数据+推送 | 我的课表在这里，调课通知会推给我 |
| 第二层（信息） | 发帖历史+收藏 | 我的帖子、回复、收藏都在这里 |
| 第三层（社交） | 圈子+关注关系 | 我关注的圈子、我的话题讨论 |
| 第四层（交易） | 信誉分+交易记录 | 我的 4.9 信誉分，23 次成功交易 |
| 第五层（身份） | 认证身份 | 已经认证过了，不想再认证一遍 |

## 四、从问卷痛点反推产品优先级

以调查问卷 Q17 的 28 项痛点为依据，和五层架构映射：

| 优先级 | 痛点 | 所属层 | 解决后效应 |
|:-----:|------|-------|----------|
| 🔴 P0 | 课表变动不知道 / 成绩查起来麻烦 | 第一层 | **每日打开理由** |
| 🔴 P0 | 学校通知分散在各个群容易漏 | 第二层 | **取代群通知** |

| 🟠 P1 | 失物招领没渠道 | 第四层 | **低频但强粘性** |
| 🟠 P1 | 想匿名吐槽没地方 | 第三层 | **社交引擎** |
| 🟡 P2 | 圈子太窄不认识其他人 | 第三层 | **社交扩展** |

## 五、一句话总结

> **CampusLink 的目标不是做一个"更好的 QQ"，而是做一个 QQ 做不了的"校园专属层"——把课表、成绩、交易、失物、通知、圈子这些零散的需求，在一个身份认证体系下整合成闭环，让学生的校园生活从"在 5 个 App 里反复横跳"变成"在一个地方完成所有事"。**

每一层单独拿出来都抵不过一个专门的 App（课表不如超课表专门、交易不如闲鱼专门），但**五层叠加 + 身份信任体系 + 校内场景原生适配**，构成了 QQ/微信无法复制、闲鱼/超课表无法覆盖、新产品无法冷启动的综合壁垒。

这不是功能竞赛，这是**场景所有权**的争夺——谁拿下了"校园生活"这个场景，谁就拥有了这个用户的校园时光。
